# Startup sweep — recovering what a crashed run left behind

Extracted from `agents/splinter.md` step 2 so the orchestrator does not carry it on every run. **Loading trigger:** step 2 of *The end-to-end run*, before this run writes its own brief — read this file when `.claude/run/` is non-empty, or when a worktree under `.claude/worktrees/` exists. On a clean checkout there is nothing to sweep and this file is not read.

The sweep is **fail-safe by construction: it deletes only on positive proof of death, never on the mere absence of a liveness signal** — anything ambiguous (missing, unparseable, or an inconclusive probe) is treated as alive and left alone, never the reverse.

2. **Startup sweep, then gather context & write the shared brief (do this before any dispatch).** Before writing this run's own brief, sweep artifacts a prior run left behind on a crash or a `Blocked` stop that skipped *Run cleanup*, so they never silently accumulate. The sweep is **fail-safe by construction: it deletes only on positive proof of death, never on the mere absence of a liveness signal** — anything ambiguous (missing, unparseable, or an inconclusive probe) is treated as alive and left alone, never the reverse.
- **Sweep lock.** Guard every step below with a short-lived lock so two runs starting at once can never interleave their sweeps and observe each other's half-written state. Key it on the repository-wide common git dir, not the current toplevel (`git rev-parse --git-common-dir`) — the worktree half below is itself repository-global (`git worktree prune|list|remove|unlock` operate on the whole repo, not one toplevel), so a run started inside `.claude/worktrees/agent-*` must contend on the very same lock as one started in the main tree, never a different one scoped to its own toplevel.
Create the lock's parent directory before the loop: this step runs before this run's own brief is written, so `.claude/run/` (and its common-git-dir equivalent) may not exist yet on a fresh checkout, and `mkdir` on a missing parent fails with ENOENT forever, never EEXIST — an unconditional `until mkdir ... ; do ... ; done` with no `mkdir -p` first hangs step 2 on every first run in a new project.
     ```bash
     LOCKROOT="$(git rev-parse --git-common-dir)"; mkdir -p "$LOCKROOT/agent-run"
     LOCK="$LOCKROOT/agent-run/.splinter-sweep.lock"
     tries=0
     until mkdir "$LOCK" 2>/dev/null; do
       sleep 0.2; tries=$((tries+1))
       if [ "$tries" -eq 51 ]; then
         # steal ONLY on a confirmed-dead holder — check kill -0's OWN exit status first, never a
         # downstream grep's (a live same-UID holder prints nothing, which must never read as dead)
         holder_pid="$(sed -n 's/^PID=//p' "$LOCK/holder" 2>/dev/null)"
         case "$holder_pid" in ''|*[!0-9]*) holder_pid='' ;; esac
         probe="$(LC_ALL=C kill -0 "$holder_pid" 2>&1)"; rc=$?
         if [ -n "$holder_pid" ] && [ "$rc" -ne 0 ] && ! printf '%s' "$probe" | grep -q 'not permitted'; then
           rm -rf "$LOCK"; tries=0   # confirmed-dead: steal and retry acquiring
         else
           echo "sweep lock held by a live/unreadable holder — skipping this run's sweep" >&2; skip=1; break
         fi
       fi
     done
     [ -z "$skip" ] && printf 'PID=%s\nSLUG=%s\nSTARTED=%s\n' "$PPID" "<source-slug>" "$(date -u +%FT%TZ)" > "$LOCK/holder"
     ```
Unlike the per-brief append lock's bounded steal (safe there because an append takes milliseconds), the sweep runs `git worktree prune|list|remove|unlock`, N× `kill -0`, and `rm -f` — reachable minutes on a large repo — so an unconditional, repeating steal would tear the lock away from a genuinely live sweep instead of a dead one. The holder file (`PID`/`SLUG`/`STARTED`, mirroring the write-lock holder) is what makes a confirmed-dead-gated steal possible at all: a lock with no holder file, or a live/EPERM holder, is **never** stolen — skip this run's sweep and report it rather than guessing. Run the sweep, then `rmdir "$LOCK"`.
This is separate from, and much shorter-lived than, the write-lock above — every run, including analysis-only, takes it for the sweep's duration only, never for the whole run.
   - **One PID source, one fixed field, format-validated before any shell use.** Every `## PID` / `pid <N>` / lock-holder `PID=` value below is this run's `$PPID` — **never `$$`**, the ephemeral PID of the single Bash subshell one tool call runs in, already dead moments after that call returns (empirically verified: two consecutive Bash calls in this environment report two different `$$` values but an identical, stable `$PPID` — the same value the write-lock holder above records, so every mechanism in this file agrees). A brief can carry attacker-influenced tracker text (see *Shared task brief* → `## Gathered context`), so a `## PID` or `pid <N>` token is data to parse, never a trusted control value.
     - **Brief `## PID`:** a fence-based "read only the lines before the first fenced block" boundary is **not** a trust boundary — measured against the briefs actually on disk, one carries no fenced block at all, making its "header region" the whole file, gathered-context included.
The real boundary is **position, not content**: `## PID` is written atomically together with the title (see *Atomic, PID-first brief creation* below), landing on the file's second line — but read by scanning only the file's **first 5 lines**, stopping at the first match, rather than requiring the literal second line: natural markdown commonly inserts one blank line after an H1 (measured against the briefs actually on disk, none put `## PID` on the literal second line), and a rule that breaks on that shape makes every such brief permanently unsweepable.
Five lines stays far short of `## Source` / `## Language` / `## Gathered context` in the brief layout, so the attacker-controlled tracker payload in `## Gathered context` can never fall inside the scanned window — this widens the **position** bound, it never turns the check into a **content**-based one. Parse each candidate line with a full anchor requiring digits immediately followed by a space or tab — `^## PID[ \t]+([0-9]{1,7})[ \t]` — never `\s+` (crosses a newline onto a value written on the next line) and never `\b` (admits the leading digits of a timestamp, e.g. capturing `2026` out of a line that writes the timestamp before the PID). A file with no matching line inside that window is treated exactly like a missing `## PID` — never a match found further down.
     - **Worktree `pid <N>` (lock reason):** require the captured token to match `^[0-9]{1,7}$` inside the `locked <reason>` porcelain line.
     - **Lock-holder `PID=` (write-lock and sweep-lock holder files):** reject an empty or non-numeric token before it ever reaches `kill -0` — `case "$holder_pid" in ''|*[!0-9]*) holder_pid='' ;; esac` — so a truncated or half-written holder file (the exact state a lock exists to make observers never see mid-write) fails safe to "alive" instead of probing an undefined value.
     - Either way, always double-quote it when it reaches a command (`kill -0 "$pid"`). A token that fails its anchor is **unparseable and counts as alive**; never fall back to scanning further in the file, or further into the reason string, for another token that merely looks like the real one.
- **Stale briefs.** For every `.claude/run/*.md` other than the file this run is about to write (this run's own `<source-slug>.md`), read its `## PID` line (fixed second line — see above) and probe it with `LC_ALL=C kill -0 "$pid" 2>&1`. This conflates "no such process" (ESRCH) with "process exists, no permission" (EPERM) — only a failure that does **not** mention "not permitted" is a confirmed-dead probe; an EPERM failure means the run is alive under another UID/namespace. A confirmed-dead, format-valid PID means the writing run is dead — delete the brief (`rm -f`).
Everything else — a successful probe, an EPERM probe, a missing/malformed `## PID` line, or a token that fails the format check — means a live peer run — leave it untouched: a brief with no `## PID` line (predates this convention, is mid-write, or is malformed) is never treated as safe to delete, because *not mine* is not the same fact as *not alive*.
**Known residual limitation (declared, not silent):** this probe only ever proves "PID N no longer exists," never "the run this brief belongs to is gone" — if the host process behind a still-relevant run genuinely exits and resumes under a new PID (a session reconnect), its old recorded PID reads confirmed-dead while the run itself continues, and no local, network-free PID check can tell that apart from real abandonment (the alternative, corroborating with the run's own tracker outcome per `write-lock-staleness-needs-corroborating-evidence-not-bare-pid`, needs a live tracker call this lightweight, pre-dispatch step deliberately does not make).
This mirrors the already-accepted DNS-rebinding gap in `attachment-download-urls-need-an-ssrf-host-guard` — a rare, documented residual, not a hole nobody noticed.
- **Stale worktrees.** Run `git worktree prune` first (always safe — it only clears administrative state for worktrees whose directory is already gone). Then, for every remaining `.claude/worktrees/agent-*` entry in `git worktree list --porcelain`: when it carries a `locked <reason>` line whose reason contains a format-valid `pid <N>` token, extract and probe it the same way — a live PID means a peer's CR pass is actively using that worktree, **never remove it**, and the same EPERM-means-alive rule applies; only a confirmed-dead PID means a stale lock left by a crashed run — `git worktree unlock` it, then it is safe to remove.
**An entry with no `locked` line at all, or a `locked` line whose reason carries no format-valid `pid <N>` token, is left in place — never removed.** Every CR worktree is now required to lock itself with a `pid <N>` token at creation (`agents/leonardo.md` *Review worktree*), so an unlocked entry is anomalous rather than a normal stale-and-safe state — report it instead of guessing. Remove with `git worktree remove <path>` only after a confirmed-dead unlock (never `--force` on a worktree carrying uncommitted changes — verify it is clean first, mirroring *Run cleanup*'s CR-worktree cleanup), then `git worktree prune` again.
   - **Atomic, PID-first brief creation.** Write this run's own brief atomically: compose the complete initial content — the `# Task brief — <source>` title, then `## PID <digits> <ISO-8601>` as the file's fixed **second line** (this run's own `$PPID`, then a space, then the current UTC timestamp, in that exact order, on one line — never split across lines, never reordered) — in a temp file inside `.claude/run/`, then `mv` it into place, so no peer's sweep can ever observe the file between its creation and the `## PID` line landing on its fixed position.
- **Probe the same-slug brief before that `mv` — a peer may already own this path.** *Stale briefs* above deliberately skips this run's own `<source-slug>.md`, so the one brief the sweep never probes is the one this run is about to overwrite. That exclusion is correct for the sweep — you do not delete a file you are about to write — but it leaves the collision uncovered, and the collision is real rather than theoretical: *Concurrency & the working-tree write-lock* lets any number of analysis-only runs overlap freely with each other and with one writing run, and an analysis-only run takes no write-lock, so nothing serialises two runs resolving the **same** source.
A full-delivery run on `#200` and an analysis-only run on `#200` derive the identical slug and therefore the identical path.
- **Apply the gate that already exists, to this one file too.** When `.claude/run/<source-slug>.md` is already present, read its `## PID` with the same fixed-position, format-validated anchor *Stale briefs* uses (`^## PID[ \t]+([0-9]{1,7})[ \t]`, first match inside the first 5 lines) and probe it with the same `LC_ALL=C kill -0 "$pid" 2>&1` confirmed-dead gate. Three verdicts, in this order. A PID **equal to this instance's own `$PPID`** is not a peer at all — it is this run's own brief from an earlier pass through this step, so re-entry is a no-op: keep the existing file and continue, exactly as the claim contract treats a re-entrant claim (`@rules/compound-engineering/tracker.md` *Claim a tracker issue before working on it*).
Check this **first**, or the next verdict blocks the run against itself: this run's own PID is by definition alive, so it would read as a live peer. A **confirmed-dead, format-valid** PID belonging to a different process means the run that wrote it is gone and the path is yours to take — proceed with the `mv`. **Everything else — a successful probe of another PID, an EPERM probe, a missing or malformed `## PID`, or a token failing the format check — is a live peer**: stop with **`Blocked: a live run holds the brief for this slug`**, naming the slug, and overwrite nothing.
This is the same fail-safe default the sweep, the write-lock reclaim, and *Run cleanup*'s ownership gate all apply — *not mine* is not the same fact as *not alive* — and it is the whole point of reusing the existing mechanism rather than inventing a second one. **Known residual limitation (declared, not silent):** the probe and the `mv` are two steps, so two runs that both probe an absent brief before either writes can still both proceed, and the second `mv` wins. The gap is the microseconds between the two, against a collision window that was previously the whole run — the same shape, and the same accepted trade-off, as the claim contract's gap between its re-read and its apply.
Closing it fully needs an exclusive create the atomic-`mv` requirement above rules out, since the `## PID` line must land in the same operation as the file.
   - **The two ledgers follow the brief's verdict, never their own.** `${BRIEF%.md}.dispatches` and `${BRIEF%.md}.audit` are created beside the brief, and *Audit trail ledger* says to create the audit file **empty** — which truncates a live peer's accumulated trail just as surely as the `mv` overwrites its brief. Create either file only once the probe above has cleared the path; on a `Blocked` verdict neither is created and neither is touched.
   Then run the gather phase and assemble the run's shared memory at `.claude/run/<source-slug>.md` per *Shared task brief* above — the source, this run's own `## PID` (written atomically as described just above), the gathered context, and your work-breakdown plan. Every specialist you dispatch from here on receives this brief's absolute path, reads it first, and appends its handoff to it. On an analysis-only run (step 3) the brief is still worth writing so `leonardo` inherits the gathered context.
